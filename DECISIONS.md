# Decisions

## Preserve package boundaries and strictness

Retain the original discovery, audit, outreach, copy and template architecture. Keep the original pipeline TypeScript strict settings, including `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, and unused-symbol checks. The smaller portfolio scope excludes operational lead shortlisting, deployment orchestration, live mail workers and the founder's personal site.

## Treat missing evidence as unavailable

Unknown measurements cannot become failed checks or invented scores. Outreach requires at least two decided failures. Tests prove that an unreachable fixture creates only unavailable verdicts and that missing Lighthouse results remain unavailable.

## Make the useful path offline

The demo uses a small synthetic Places response and explicit browser-evidence fixtures. It disables fetch in-process, writes reviewable artifacts, and labels simulated evidence. Actual external integration is optional and unverified here. This keeps the architecture demonstrable without paid keys, live businesses or credentials.

## Reuse the source design system

Keep five synthetic business configurations and all five design families. Use one typed content contract and derived validated design payloads rather than five unrelated page implementations. Remove client registry entries, private content, private previews, arbitrary file imports and account routing.

## Keep the interactive form honest

The default template resolver forces a local `demo` mode. Validation, offline feedback and success states remain testable, while no form data leaves the browser or is stored. The UI identifies the operation as a simulation. The retained component's worker/mailto branches are reference code and are not selected by the public sample resolver.

## Generate CSP from the built pages

Inline scripts have per-config bytes. Compute their hashes from actual HTML and verify `_headers` against those bytes. Script CSP never uses `unsafe-inline`; style attributes require a disclosed style allowance. This provides a static deployment example without attaching an account or publishing anything.

## Keep generated data outside version control

Commit only synthetic inputs, source and selected screenshot assets. Ignore local credentials, actual lead files, caches and outputs. Initialize a new local repository with one root commit; source commit history is not part of this project.

## License the extraction with the owner's selected MIT license

The owner selected MIT for the extraction on October 12, 2026. Apply it to first-party code and original/generated demo illustrations, with dependencies retaining their own licenses. No source license was present; do not imply an upstream MIT grant. Contributor and ownership review remains part of publication review, and this license grants no rights to excluded third-party data or media.

## Update affected build dependencies deliberately

The source dependency ranges resolved to older Astro, Tailwind, Lighthouse and Sharp versions with registry advisories. Migrate this extraction to Astro 7, the Tailwind 4 Vite plugin, Lighthouse 13 and current Sharp. Preserve the original design contract and React 18 form behavior. Pin `@vitejs/plugin-react` 6.1.1 because the next release's OXC peer range differs from the Astro integration's declared range. Override esbuild to the patched 0.28 series. Build, typecheck and rendered UI checks verify these targeted changes; the final registry audit is recorded in private preparation evidence.
